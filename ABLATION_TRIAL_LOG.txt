Locked architecture for this BloodMNIST phase
- BloodMNIST grayscale conversion, real data in `[0, 1]`
- Generator output via `sigmoid`
- Latent:
  - `z = [noise(62), discrete(8), continuous(2)]`
- HyperNetwork:
  - learned chunk embeddings
  - hidden widths `48 -> 48`
  - correct chunk reconstruction
- Generator:
  - split latent paths:
    - `seed_base(noise only)`
    - `seed_code(discrete only)`
    - `seed_cont(continuous only)`
  - `code_seed_scale = 3.0`
- Discriminator / Q:
  - SAME-padded full-coverage backbone
  - spatial Q head without GAP
  - brightness guard before Q
- Plumbing:
  - dynamic discriminator feature dimension
  - no hard-coded rollout / centroid feature size

What the current CA is expected to help with
- better timing of exploration vs commitment
- avoiding premature prototype hardening
- reweighting `adv / mi / div / sense / intra` when training drifts
- possibly helping PGPE escape late plateau behavior

What the current CA is not yet expected to solve alone
- true hematologic morphology disentanglement
- forcing separation on nucleus/cytoplasm structure instead of cheap proxies
- preventing clock-face or size-only coding unless those failure modes are made explicit in controller signals

CA design stance for the full paper
- The CA should be general at the optimization-framework level, not fully dataset-agnostic at the semantic level.
- The reusable part is the controller framework:
  - belief space
  - KS roles
  - rescue / adaptation logic
- The dataset-instantiated part is the semantic interface:
  - which proxy metrics define meaningful factors of variation
  - which shortcuts should be penalized or diagnosed
  - which soft bounds should be expressed in Normative KS

Working KS interpretation
- Domain KS:
  - learns which feature-representation patterns matter in the current dataset
  - acts as the semantic interpreter and trap detector
- Normative KS:
  - should express acceptable soft ranges derived from Domain-level regularities
  - should not be treated as a fully generic statistical buffer once semantic control is needed
- Historical KS:
  - serves as the rescue archive when the run collapses into shortcut solutions
- Topographic KS:
  - tracks output-structure geometry
  - helps explore output space, but should not define semantic correctness on its own

Future transfer hypothesis: IMDb hard-attention
- The same CA framework should transfer to a future HyperNetwork / PGPE hard-attention system.
- What should remain general:
  - belief-space mechanics
  - KS roles
  - explore / exploit / rescue logic
  - generic optimization-health monitoring
- What should be task-instantiated:
  - what counts as meaningful semantic control
  - what counts as a shortcut
  - which soft bounds belong in Normative KS
- Working interpretation for IMDb:
  - Domain KS should learn whether attention selections focus on sentiment-bearing spans or cheap shortcuts such as punctuation, token frequency, or positional bias
  - Normative KS should express soft acceptable ranges for sparsity, continuity, class-conditional diversity, or coverage of salient tokens
  - Historical KS should preserve pre-collapse attention policies
  - Topographic KS should track attention/output geometry without defining semantic correctness by itself

Current morphology concern to monitor
- a likely failure mode is one generic cell template reused across codes, with differences carried mostly by:
  - cell size
  - global darkness / contrast
  - nucleus orientation around the center
- `code_proto_corr_avg` is therefore a key metric in every run review

Trial BLD-A01 - Dynamic fitness weighting only
--------------------------------------------------------------------------------
Status
- Completed.
- Negative-but-useful ablation result.

Purpose
- Isolate dynamic fitness weighting from CA gradient guidance.

Command
```bash
python examples/train_bloodmnist.py \
  --gpu-id='0,1' \
  --checkpoint-interval=5000 \
  --ca-blend-coeff=0.0 \
  --disc-features=48
```

What changes relative to BLD-B00
- `--static-fitness-weights` is removed
- adaptive weighting is enabled
- CA gradient blend remains off

Question
- Does adaptive weighting alone improve late code commitment and morphology separation, or does it mainly change health / stability?

Primary comparison targets vs BLD-B00
- `code_proto_corr_avg`
- `mi_avg`
- `r_sense_avg`
- `real_fake_loss`
- image evidence that codes differ by more than size/orientation

Outcome (~100k)
- Stable, but not competitive with the static baseline on disentanglement.
- Typical late-window behavior (`~90k-102k`):
  - `mi_avg` remained low (`~0.039`)
  - `r_sense_avg` remained modest (`~0.093`)
  - `real_fake_loss` stayed healthy (`~0.609`)
  - `code_proto_corr_avg` stayed high (`~0.749`)
- Visual result:
  - clean cells
  - no major artifact regression
  - persistent one-template behavior with separation still dominated by size / darkness / nucleus placement

Observed adaptive-weight pattern (original, without balanced sampling)
- `w_adv` stayed elevated (`~0.60`)
- `w_mi` stayed too low (`~0.21`)
- `w_div` stayed suppressed (`~0.13`)
- `w_sense` stayed moderate (`~0.15`)
- `w_intra` stayed too high (`~0.12`)

Original interpretation
- The current adaptive controller acts as a conservative stability controller.
- It does not discover that MI/diversity should be emphasized more strongly for BloodMNIST disentanglement.

Rerun with class-balanced D-step sampling (`~290k`)
- Same command but without `--static-fitness-weights` and with balanced sampling.
- Broad window metrics (`~240k-290k`):
  - `mi_avg = 0.0615`
  - `r_sense_avg = 0.0880`
  - `r_intra_avg = 0.9354`
  - `real_fake_loss = 0.6287`
  - `code_proto_corr_avg = 0.7391`
  - `cell_circularity_avg = 0.4079`
  - `cell_area_var_avg = 0.002129`
  - `nucleus_offset_avg = 0.1524`
  - `stdev_mean = 0.0249`
- Final 100-iter window (`~280k-290k`):
  - `mi_avg = 0.0623`
  - `r_sense_avg = 0.0920`
  - `r_intra_avg = 0.9600`
  - `real_fake_loss = 0.6261`
  - `code_proto_corr_avg = 0.7381`
  - `cell_circularity_avg = 0.4172`
  - `cell_area_var_avg = 0.001942`
  - `nucleus_offset_avg = 0.1521`
  - `stdev_mean = 0.0245`
- Dynamic weight averages (final 200 iters):
  - `w_adv = 0.562`
  - `w_mi = 0.154`
  - `w_div = 0.144`
  - `w_sense = 0.142`
  - `w_intra = 0.120`
  - `w_shape = 0.181`
- Comparison vs B00-balanced at `~290k`:
  - MI: weaker (`0.062` vs `0.089`) — dynamic controller halves MI weight
  - r_sense: weaker (`0.088` vs `0.155`)
  - r_intra: much stronger (`0.935` vs `0.839`) — dynamic controller triples intra weight
  - real_fake_loss: stronger (`0.629` vs `0.593`) — best adversarial health of any run
  - code_proto_corr: slightly higher (`0.739` vs `0.703`)
  - cell_circ: comparable (`0.408` vs `0.432`)
- Visual read at `~270k-289k`:
  - clear cell bodies with distinct lighter cytoplasm and darker nuclei
  - multiple codes show varied nucleus shapes (round, eccentric, elongated)
  - some codes have cells that bleed into neighbors, others are well-isolated
  - image quality is the best of any completed run
- Interpretation:
  - with balanced sampling, A01 produces the highest image quality seen
  - dynamic weights trade MI/disentanglement for adversarial health + within-code consistency
  - the controller halves w_mi (0.15 vs B00's 0.30) and triples w_intra (0.12 vs 0.04)
  - this explains the MI gap: constant MI pressure (B00) outperforms reactive MI pressure (A01)
  - key insight: static MI weight + dynamic adversarial/intra weights may be the optimal combination

Key findings:
1. Class-balanced D-step sampling is a strict improvement (adopted as standard).
2. CA gradient blend hurts MI at every dose and configuration tested.
3. Dynamic weights improve image quality and r_intra but halve MI pressure.
4. Static MI + dynamic rest (hybrid) is the best combined configuration.
5. The MI vs adversarial quality tradeoff is a fundamental budget constraint.
6. The CA framework mechanics work (trap detection, normative bounds, KS updates)
   but the gradient blend mechanism conflicts with PGPE's REINFORCE signal.
7. For the full paper, the CA's value is diagnostic: it reveals *why*
   disentanglement fails (geometric shortcuts, MI gradient interference) and
   informs the architecture for transformer attention where the CA's
   intervention surface (discrete attention masks) is better suited to its
   strengths.

Trial BLD-A05 - Class-balanced D-step sampling
--------------------------------------------------------------------------------
Status
- Completed.
- Class-balanced sampling is now the standard for all future runs.

Purpose
- Fix upstream signal quality by giving the discriminator a balanced real distribution.
- BloodMNIST is imbalanced: class 6 (19.5%) is sampled 2.7x more than class 4 (7.1%).
- The D-step sampled uniformly from the full dataset, so the discriminator's feature space
  over-represents common classes and under-represents rare ones.
- MI and r_sense both depend on D's features, so the imbalance degrades signal quality
  for all downstream components.

What changes relative to BLD-B00
- `sample_batch()` in trainer.py now accepts per-class index arrays
- Each D-step batch draws an equal number of images from each class (8 per class for batch=64)
- No CA changes, no new metrics, no architecture changes

Outcome
- Integrated into BLD-B00 rerun (`~290k`). See BLD-B00 section for full metrics.
- Balanced sampling is a strict improvement: r_sense, r_intra, and rfl all improved or matched.
- Spatial jitter (±2 pixel `jnp.roll`) was tested and rejected:
  - collapsed adversarial fitness when combined with CA (A05+jitter run)
  - at 28x28, shift is too large a fraction of image size
  - jitter code was reverted

Question (answered)
- Does balanced D-step sampling improve disentanglement quality or adversarial health?
- Yes. r_sense improved from 0.140 to 0.155, r_intra from 0.749 to 0.839, rfl from 0.582 to 0.593.
