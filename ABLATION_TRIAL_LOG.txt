Locked architecture for this BloodMNIST phase
- BloodMNIST grayscale conversion, real data in `[0, 1]`
- Generator output via `sigmoid`
- Latent:
  - `z = [noise(62), discrete(8), continuous(2)]`
- HyperNetwork:
  - learned chunk embeddings
  - hidden widths `48 -> 48`
  - correct chunk reconstruction
- Generator:
  - split latent paths:
    - `seed_base(noise only)`
    - `seed_code(discrete only)`
    - `seed_cont(continuous only)`
  - `code_seed_scale = 3.0`
- Discriminator / Q:
  - SAME-padded full-coverage backbone
  - spatial Q head without GAP
  - brightness guard before Q
- Plumbing:
  - dynamic discriminator feature dimension
  - no hard-coded rollout / centroid feature size

What the current CA is expected to help with
- better timing of exploration vs commitment
- avoiding premature prototype hardening
- reweighting `adv / mi / div / sense / intra` when training drifts
- possibly helping PGPE escape late plateau behavior

What the current CA is not yet expected to solve alone
- true hematologic morphology disentanglement
- forcing separation on nucleus/cytoplasm structure instead of cheap proxies
- preventing clock-face or size-only coding unless those failure modes are made explicit in controller signals

Current morphology concern to monitor
- a likely failure mode is one generic cell template reused across codes, with differences carried mostly by:
  - cell size
  - global darkness / contrast
  - nucleus orientation around the center
- `code_proto_corr_avg` is therefore a key metric in every run review

Trial BLD-B00 - Locked non-CA BloodMNIST baseline
--------------------------------------------------------------------------------
Status
- Active reference baseline.
- Continue running to at least `100k` unless adversarial health breaks.

Command
```bash
python examples/train_bloodmnist.py \
  --gpu-id='0,1' \
  --checkpoint-interval=5000 \
  --ca-blend-coeff=0.0 \
  --static-fitness-weights \
  --static-mi-sense-ramp \
  --static-w-div=0.18 \
  --static-w-sense=0.08 \
  --static-w-intra=0.03 \
  --static-div-ramp-target=0.16 \
  --static-div-ramp-start-iter=12000 \
  --static-div-ramp-end-iter=28000 \
  --static-sense-ramp-target=0.14 \
  --static-sense-ramp-start-iter=12000 \
  --static-sense-ramp-end-iter=28000 \
  --static-intra-ramp-target=0.04 \
  --static-intra-ramp-start-iter=12000 \
  --static-intra-ramp-end-iter=28000 \
  --disc-features=48
```

Current read (~58k)
- Stable adversarial health:
  - `real_fake_loss` roughly `0.55 - 0.60`
- MI has become clearly positive:
  - `mi_avg` roughly `0.07 - 0.08`
- Code separation exists but is still moderate:
  - `r_sense_avg` roughly `0.12 - 0.14`
- Images are clean and smooth:
  - circular cell bodies
  - no major edge-connection artifact
- Main remaining weakness:
  - disentanglement is still dominated by easy morphology axes such as size, darkness, and nucleus placement/orientation

Evaluation protocol for all BloodMNIST ablations
--------------------------------------------------------------------------------
Compare each run at:
- `20k`
- `60k`
- `100k`
- `150k` if healthy

Record side-by-side:
- `mi_avg`
- `mi_max`
- `r_sense_avg`
- `r_intra_avg`
- `real_fake_loss`
- `spread_avg`
- `code_proto_corr_avg`
- `morph_dark_range_avg`
- `morph_center_edge_range_avg`

Visual checklist
- Are edge artifacts absent?
- Are codes still distinguished mainly by size / darkness / orientation?
- Do multiple columns still look like one template rotated around the center?
- Are any codes separating by more meaningful morphology?
- Is within-code variation still coherent?

Success criteria
- Better or equal adversarial health than `BLD-B00`
- Lower `code_proto_corr_avg` than `BLD-B00`
- More visually distinct per-code morphology than `BLD-B00`
- No return of early edge/pathology artifacts

Failure criteria
- MI and `r_sense` rise while visual prototypes remain one generic cell template
- CA destabilizes adversarial health without improving morphology separation
- Image quality regresses to noisy or edge-connected cells
