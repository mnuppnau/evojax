MNIST Hyper-InfoGAN
Ablation Trial Log
Last updated: 2026-03-06

Purpose
- Track the MNIST-first baseline after the BloodMNIST detour and the major bug-fix cycle.
- Record exact baseline/reference runs before changing weights, learning rates, or CA behavior again.
- Keep this file aligned with `PLAN.md`.

Current branch
- `claude/evolve-infogan-hypernetworks-s3r6d-67132f2-mnist-debug`

Locked architecture for all current MNIST runs
- Dataset/output scale:
  - MNIST real data in `[0, 1]`
  - Generator output via `sigmoid`
- Latent:
  - `z = [noise(62), discrete(10), continuous(2)]`
- HyperNetwork:
  - learned chunk embeddings
  - hidden widths `48 -> 48`
  - fixed chunk reconstruction (no padding-misaligned flatten split)
- Generator:
  - split latent paths:
    - `seed_base(noise only)`
    - `seed_code(discrete only)`
    - `seed_cont(continuous only)`
  - `code_seed_scale = 3.0`
- Discriminator / Q:
  - SAME-padded full-coverage backbone
  - spatial Q head without GAP
  - brightness guard before Q
- Dynamic rollout plumbing:
  - no hard-coded `256` feature-dim assumptions

Major bugs fixed before these MNIST baseline runs
1. HyperNetwork chunk misalignment in generator parameter reconstruction.
2. Wrong MNIST scale / output pairing after switching back from BloodMNIST.
3. D and Q blind spots from VALID/stride geometry.
4. Q-head GAP shortcut enabling code watermarking.
5. Latent leak where the noise path saw full `z`.
6. Hard-coded discriminator feature dimension in rollout carry / centroids.
7. Remainder-code batching bias in training and preview assembly.

Trial R00 - Archived stable reference run
--------------------------------------------------------------------------------
Status
- Archived reference, not the active run.
- User saved all images and metrics from this run.
- `checkpoint_10000.pkl` was preserved and reused for the next trial.

Command family
- `python examples/train_mnist_infogan.py --gpu-id='0,1' --checkpoint-interval=5000 --ca-blend-coeff=0.0 --static-fitness-weights`

Important behavior
- This was "legacy static":
  - `static_fitness_weights = 1`
  - `ca_blend = 0.0`
  - MI/sense still ramped because static mode had the old leak
- Effective weight regime:
  - `w_adv = 0.53`
  - `w_div = 0.16`
  - `w_intra = 0.05`
  - `w_mi = 0.30 -> 0.50` (gated ramp)
  - `w_sense = 0.14 -> 0.34` (gated ramp)
- Default PGPE/LR regime:
  - `center_lr = 0.0048`
  - `std_lr = 0.062`
  - `init_std = 0.032`
  - `lr_decay_coef = 1.0`
  - `lr_decay_steps = 100000`

Outcome
- Most stable MNIST run so far.
- Healthy discriminator balance and usable MI trend.
- Best overall image quality / semantic structure to date.
- Main remaining failure mode:
  - late semantic aliasing between a small number of code columns
  - especially the `1 / 4 / 8 / 9` family

Use
- This is the reference archive for all future image and metric comparisons.

Trial B01 - Active baseline run (resume from 10k, lower separation pressure)
--------------------------------------------------------------------------------
Status
- Active baseline run.
- Purpose is narrow: test whether slightly lower `w_sense` reduces early style-splitting without breaking the stable R00 dynamics.

Run source
- Resume from `log/mnist_infogan/checkpoints/checkpoint_10000.pkl`

Effective configuration
- `ca_blend = 0.0`
- `static_fitness_weights = 1`
- `static_mi_sense_ramp = 1`
- Static override:
  - `static_w_sense = 0.10`
- Other weights remain at the R00 legacy-static defaults / ramps:
  - `w_adv = 0.53`
  - `w_div = 0.16`
  - `w_intra = 0.05`
  - `w_mi = 0.30 -> 0.50` (gated ramp)
  - `w_sense = 0.10 -> 0.30` (gated ramp)
- PGPE/LR kept unchanged from R00:
  - `center_lr = 0.0048`
  - `std_lr = 0.062`
  - `init_std = 0.032`
  - `lr_decay_coef = 1.0`
  - `lr_decay_steps = 100000`

Why this is the first tweak
- The stable reference run already had workable dynamics.
- The earliest semantic failure was style-splitting into duplicate code columns.
- Lowering `w_sense` is the smallest change that directly targets over-separation on style axes.

Early metric window (current run, ~10.4k-12.3k)
- `real_fake_loss`: `0.522 - 0.595`, last `0.590`
- `adv_avg`: `-1.211 - -0.920`, last `-0.946`
- `mi_avg`: `-0.025 - 0.024`, last `0.002`
- `mi_max`: `0.030 - 0.051`, last `0.045`
- `r_sense_avg`: `0.109 - 0.162`, last `0.146`
- `r_intra_avg`: `0.461 - 0.967`, last `0.811`
- `spread_avg`: `0.014 - 0.039`, last `0.026`

Early image read
- Very early behavior showed a straight-`1` / slanted-`1` split.
- After lowering `w_sense`, the slanted `1`s started moving toward `2`s instead of staying locked as a second `1` column.
- This is the right thing to watch next; the run is still too early to treat it as resolved.

Decision checkpoints for B01
- `12k absolute`:
  - check whether the early duplicate-`1` pattern is already weakening
- `15k absolute`:
  - first serious semantic check
  - the slanted `1` column should be trending toward a distinct class, not another style variant
- `20k absolute`:
  - primary decision point
  - code columns should show clearer semantic commitment than R00 at the same iteration
- `25k-30k absolute`:
  - stop / retune if duplicate columns are still fixed in place

Comparison protocol against R00
- Compare both:
  - absolute iterations: `12k`, `15k`, `20k`, `25k`, `35k`
  - relative-to-resume windows: `+2k`, `+5k`, `+10k`, `+15k`
- Primary image questions:
  1. Did the duplicate `1` family shrink?
  2. Did the reassigned column become a real new digit rather than a style variant?
  3. Did any new code collapse appear elsewhere?
  4. Are within-code samples still coherent and readable?
- Primary metric questions:
  1. Does `real_fake_loss` stay in the healthy band (`~0.52-0.60`)?
  2. Does `mi_avg` stay near or above `0` by `15k-20k`?
  3. Does `r_sense_avg` remain non-collapsed without driving duplicate style columns?
  4. Does `r_intra_avg` stay healthy rather than collapsing into near-identical samples?

Current interpretation
- B01 is the new active baseline run.
- R00 remains the archived reference pack.
- No further weight or LR changes should be made until the `20k` comparison against R00 is complete.
